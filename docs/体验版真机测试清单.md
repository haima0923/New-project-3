# 货小玲体验版真机测试清单

这份清单给非技术测试使用。你不用判断代码，也不用猜原因；只需要照着输入、截图、记录结果。

> **当前是 P0 OPEN 候选快照，不是发布基线。** `record-flow-gate --live-ai`
> 暂停作为发布依据，standard/deep 的合法空业务 JSON 也存在被当作成功的风险。
> 两个 P0 修复并回归通过前，本清单只能用于人工观察，不能据此批准上线。

## 先看结论

- 历史工作树曾生成“1,490 通过、0 未通过”的本地/分流报告；本次冻结没有重跑，历史报告也不代表当前生产全链路。
- 这不等于真实 AI 和真机已经通过：体验版测试仍是决定能不能继续上线的重要依据。
- 本清单共 60 题：20 道真实语音、15 道粘贴聊天、10 道长确认卡、10 道网络和等待时间、5 道保存后回查。
- 测完 60 题，不代表覆盖世上所有说法；它覆盖了老板最常用、最容易出大问题的输入方式。之后每发现一个新问题，都要把那句话永久加进题库。

## 0. 测试前准备

1. 确认手机打开的是刚上传的**体验版**，不是开发工具预览版。
2. 用一个专门测试的微信号或确认测试数据可以随后删除；不要把“验收李姐”等测试记录混进正式生意数据。
3. 准备普通网络（Wi-Fi 或手机流量）；网络题再按题目要求断网或使用弱网。
4. 每题都从“记一笔”重新开始。没有特别说明时，不要提前修改系统识别出来的字段。
5. 看到确认卡后，先展开“本次整理说明”，记下“总共用了几秒”。再截图，最后才可以修改或保存。

## 1. 每一题都按这 5 步做

1. **输入原话**：语音题按住说出题目；聊天题原样粘贴。语音转出的文字如果和原话不同，也要一并截图。
2. **看它怎么理解**：核对客户、业务类型、商品、数量、单价、金额、交期、商品件数。
3. **看它为什么这样处理**：展开“本次整理说明”，记录是本地整理还是联网整理、总等待时间、是否提示不确定。
4. **看页面能不能操作**：长卡片向下滑到底，确认所有实际出现的操作按钮都能看到、能点到，不被底部导航栏挡住。
5. **看保存后是否正确**：只有预期允许保存的题才保存；再去“记录”或“问一句”核对。预期“待整理”的题，不能被正式保存。

### 怎么判定不通过

下列任一情况都是**红色问题**，不要因为别的题通过而忽略：

- 凭空造出客户，例如把“老板今天”当成客户。
- 把“20 块钱一个”拆成第二个商品，例如“块钱”。
- 客户、商品、数量、单价、金额、交期、商品件数中有一个关键值错。
- 信息不全、两笔业务混在一起、收款关联不明，却被直接正式保存。
- 卡片按钮被底部导航栏遮住或点不到。
- 普通联网整理超过 8 秒、复杂联网整理超过 25 秒还没有明确结果；或一直转圈。

文字不够好看、提示不够自然等问题也请记录，但可以标为“黄色问题”。

## 7. 测完后怎样把结果发给我

优先发下面四类材料，不需要自己分析：

1. 所有不通过题的“确认卡完整截图”，尤其要包含原话、识别字段、底部按钮。
2. 展开“本次整理说明”的截图，必须看得到本地/联网方式和总时间。
3. 每个网络题的实际秒数。
4. 一张保存后记录页或“问一句”结果截图。
