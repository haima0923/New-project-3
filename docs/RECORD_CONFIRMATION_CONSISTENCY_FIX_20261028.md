## 范围和安全边界

- 链路：首页文字/粘贴/语音终稿 → 完整页 → 识别 → 确认卡 → 保存前检查；在隔离测试中复查业务写入。
- 生产修改仅为 `pages/input/input.js` 与 `utils/parse-safety.js`。
- 未修改 `utils/parser.js`、`utils/business.js`、`utils/storage.js`、配置、发布文件和服务端。
- 业务类型仍不确定、类型冲突、混合业务、AI returned_uncertain 的风险继续保留；缺交期不被清除。
- NO_RECORD 的领域阻断继续存在，正式保存、待整理及 Deep 入口不开放。观察报告保留 `rawMissingFields`，仅将真实中性页面的可见缺字段记为空；错误提示或保存入口出现时不能被此规则隐藏。
- 真正人工确认、同名商品、删除/替换商品后的证明绑定继续接受专项检查，没有通过忽略元数据断言来放行。
- 首页转交只接受白名单字段。语音来源、解析来源和实际目标页面分别判断；不能夹带路由、人工证明或保存授权。
- 未提交 commit、push、合并、上传或发布；原 Windows 工作区备份和此前未提交修改保留。
