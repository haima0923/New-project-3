# 货小玲多 Agent 协作流程

## 主控 Agent 职责

- 理解用户本轮目标，确认允许修改范围。
- 拆分任务，判断哪些可以并行，哪些必须串行。
- 汇总代码、产品、测试、风险等结论。
- 控制最终改动范围，避免业务代码被误改。
- 输出清晰的完成结果、验证情况和下一步建议。

## 代码地图 Agent 职责

- 只读梳理项目结构、页面入口、工具函数、存储逻辑和配置文件。
- 标出关键文件和潜在影响范围。
- 说明当前实现与任务目标的关系。
- 不直接改代码，除非主控 Agent 明确分配且文件范围清楚。

## 产品规则 Agent 职责

- 检查任务是否符合货小玲产品定位。
- 防止功能膨胀成 ERP、CRM、财务软件或复杂管理系统。
- 审核文案是否符合义乌中小工厂老板使用语境。
- 判断是否存在假数据、虚假能力或过度设计。

## 解析器 / AI Agent 职责

- 识别当前 `utils/parser.js` 是本地规则解析器，不是真实大模型。
- 分析记一笔输入如何被解析为欠款、订单、报价、跟进、发货或备忘。
- 评估误解析、漏解析和字段缺失风险。
- 规划后续真实大模型、语音转文字接入边界，但不能假装当前已经具备。

## 业务流转 Agent 职责

- 梳理欠款、收款、订单、报价、跟进、发货等轻量业务状态。
- 检查状态变化是否来自用户输入或明确操作。
- 防止自动生成没有依据的业务结果。
- 确保业务流转能被老板理解和使用。

## 小程序 UI Agent 职责

- 检查微信小程序页面结构、交互、空状态和移动端体验。
- 确保首屏优先展示真实关键事项。
- 使用老板能听懂的短文案。
- 避免复杂表单、复杂导航和重型后台风格。

## 测试与回归 Agent 职责

- 根据任务范围制定最小但有效的验证清单。
- 覆盖空状态、有数据、长文本、误解析、状态变更等关键场景。
- 记录验证命令、验证结果和未覆盖风险。
- 不用假数据冒充真实业务数据。

## 配置与发布风险 Agent 职责

- 检查 `app.json`、`project.config.json`、环境配置、权限、构建和发布相关风险。
- 识别小程序发布前可能影响审核、运行或用户数据的改动。
- 配置文件改动必须单独说明原因和风险。
- 没有明确任务时，不主动修改配置和发布相关文件。

## 可以多 Agent 并行的任务

- 只读代码地图梳理。
- 产品规则检查。
- UI 文案和空状态评审。
- 解析器风险分析。
- 测试清单设计。
- 配置风险只读检查。
- 文档草案审阅。

## 必须单 Agent 串行的任务

- 修改同一个文件。
- 修改业务状态流转。
- 修改解析器规则。
- 修改本地存储结构。
- 修改小程序页面入口或路由配置。
- 修改发布、权限、构建配置。
- 涉及数据迁移、兼容处理或真实后端联调的任务。

## 日常使用流程

1. 主控 Agent 先确认本轮目标和允许修改范围。
2. 只读分析可以分配给多个 Agent 并行完成。
3. 主控 Agent 汇总分析结果，确定最小修改方案。
4. 涉及代码修改时，按文件和模块串行执行，避免互相覆盖。
5. 修改后由测试与回归 Agent 提供验证清单或执行验证。
6. 产品规则 Agent 复核是否仍符合货小玲定位。
7. 主控 Agent 输出改动文件、是否触碰业务代码、验证结果和下一步建议。
