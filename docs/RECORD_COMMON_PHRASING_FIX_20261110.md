## 1. 范围与启动判断

- **任务类型**：局部修复，按受影响的完整用户链路验收，不承诺所有口语或语音均已可用。
- **用户链路**：完整页或首页输入 → 识别 → 逐项补充 → 确认 → 一次保存 → 记录页和详情重读；缺客户也可主动存待整理。
- **复查角色**：产品、用户链路、Parser 安全和回归视角，由同一实现者串行处理，没有启动独立子 Agent。
- **生产修改**：仅 `utils/parser.js`，限定明确录入指令的识别上下文与否定/未确认边界。
- **测试修改**：新增 `scripts/record-common-phrasing-tests.js`；扩展用户链路测试；登记离线白名单；修订 3 个 Case 文件的 9 个来源标记以及 Runner 对应来源自测。
- **禁止修改**：business、storage、页面、app/config、服务端和发布配置。本轮没有新增这些区域的改动；保留全部此前未提交工作。
- **风险**：涉及本地 Parser，重点防止指令冒充客户/商品、否定请求被保存、缺字段自动补造和证据位置失真；不改变核销或关系授权。
- **最小范围**：仅处理开头明确请求；不全局删除“记”“单”“笔”等字，不扩大商品词表，不改真实模型或保存策略。
- **实施授权**：用户接受上一轮建议并明确委托继续技术实现；未提交、推送、合并或发布。

人工验收标准：输入“给王总记一单帆布袋500个，6元一个，8月15日交”，商品应为“帆布袋”、金额 3000；
不写客户则追问客户，不写交期则继续追问交期。原话保持完整，确认前不保存，保存后可在记录页和详情看到。
“先别记”“要不要记”和前后说法冲突时不能直接正式保存。例子日期来自固定合成测试时钟，并非当前真实业务。

## 2. 用户可见结果

| 输入或操作 | 结果 |
| --- | --- |
| 记一单帆布袋500个，6元一个 | 识别订单、帆布袋、500个、3000元；客户和交期仍须补充 |
| 给王总记一单…… / 请帮我记一单…… | 指令不再混入商品名，明确客户继续保留 |
| 记个订单…… / 记一下报价…… | “记个”“记一下”不再被当作客户 |
| 记一笔帆布袋500个，6元一个 | 不仅凭“记一笔”猜订单，保留可识别事实和原话 |
| 先别记一单…… / 要不要记一单…… | 未取得明确记录要求，不允许正式保存 |
| 记一单……还没下单 / 记一下报价……暂时不报价 | 记录指令不覆盖后续否定事实，停下来核对 |
| 缺客户，用户主动存待整理 | 只新增待整理，不创建客户或订单；商品名和原话正确 |
| 记事本、记忆棉、单据夹、备忘录 | 商品名不因含“记”“单”等字被误删 |

实现使用等长空白遮蔽识别上下文中的指令部分，保留明确客户和所有原始文本。
订单/报价指令的 Evidence 仍绑定原句位置；原话、粘贴原聊天、提取内容和关系指代继续保留。
泛指记录请求不产生订单 Evidence，否定、试探、条件请求和冲突均不能直接保存。
复杂定金、关系选择、金额冲突、同名客户、超额和 Provider 生产资格保护继续沿用既有规则。
