## 微信工具中的实际发现

1. 输入“王总下单三件套500套，每套6元，明天交”，实际确认卡显示三件套、500套、6元/套、3000元、2026-11-13。
2. 确认卡可滚动查看字段和原话，底部操作按钮能看到并点击。
3. 保存后记录页和详情页一致，原始内容保留；重新编译后仍能看到同一订单及首页交货提醒。
4. 输入“赵姐下单三件套，每套6元，明天交”，系统分别询问数量和单位，没有把商品名中的“三件”当采购数量。
5. 回答500、套后，修复前确认卡的该项金额和总金额为空，总金额区域被隐藏，但保存按钮仍可用。
6. 修复后重新编译，从相同原话开始逐项回答，确认卡在保存前显示该项3000、总额3000。
7. 实际双击“确认保存”后，记录页只有一笔赵姐订单；加上此前王总订单共两笔。
8. 赵姐订单详情中为500套、6元/套、3000元，原话仍是最初缺数量的输入，没有被补答覆盖。
9. 再次实际重新编译，首页保留两笔订单及各自提醒，没有重复新增。

这些是电脑微信运行时/WXML与真实 `wx` Storage API 的隔离测试，不是手机真机结果。
测试设备为工具中的 iPhone 12/13 模拟器，页面宽390px；未覆盖所有屏幕、所有页面或所有极长确认卡。

## 根因与最小修复

`answerAssistantQuestion()` 原先只更新商品字段，再汇总已有单项金额。
它没有像手动编辑确认卡那样按数量与单价重算；`buildOrderAmountSummary()` 因金额空而隐藏总额。
保存层随后会补算，所以只验证最终订单3000的旧测试漏掉了用户确认时看不到金额的问题。

本轮只在可信商品补答分支重算当前项：

- 数量、单价和计数单位已经明确时，单位一致才做确定性乘法。
- 已有手工单项金额继续保留。
- 原话明确总价、用户手工总价不被计算价覆盖；有冲突继续询问。
- 单位不同不猜换算；其他商品不随本次答案改动。
- 原始输入、问题版本、itemKey 和可信回答凭据要求保持。

没有修改安全政策、题库 Expected 或放宽保存门禁。
