# 合法报价转订单完整保存测试合同 v1

这是一组独立的失败优先测试，不计入核心 120 题，也不改变既有报价选择专项或 `REL-008` 的输入、期望和结论。

它从真实报价列表页面开始，执行真实 `startConvert()`（开始转换）、`changeConversionDeliveryDate()`（选择交期）、`confirmConvert()`（确认转换）、`convertQuotationToOrder()`（报价转订单业务函数）和 `saveState()`（正式保存），再通过真实 `getState()`（读取状态）核对持久化结果。

## 运行方式

```text
node tests/record-e2e/runner-tests/quotation-to-order-save-surface-tests.js
node tests/record-e2e/quotation-to-order-save-v1/run.js --repeat 2
node tests/record-e2e/quotation-to-order-save-v1/run.js --case-id REC-E2E-Q2O-001
```

测试状态含义：

- `PASS`：产品行为满足合同。
- `CASE_FAIL`：案例失败；运行器已正常执行，但当前生产行为不满足产品合同。
- `RUNNER_ERROR`：运行器错误；测试基础设施本身没有完成执行。
- `BLOCKED`：阻塞；前置条件不具备，案例没有真正执行。
- `SURFACE_ERROR`：测试表面错误；页面路径、动作映射、方法调用或观测接线失效。

## 文件职责

- `manifest.json`：固定测试组 ID、28 条用例清单和“不计入核心 120 题”的边界。
- `cases.json`：只表达产品合同。每条包含初始持久化状态、用户动作、页面结果、保存次数、最终状态、必须不存在的数据和生产缺口；不把当前红灯写成期望。
- `fixtures.json`：报价转单专用状态夹具，覆盖单商品、多商品、旧顶层字段、脏关系、不可转换和金额冲突。
- `load-contract.js`：严格核对 Manifest（清单）、案例和夹具，递归解析夹具继承。
- `page-actions.js`：使用中央页面动作注册表调用真实报价页面方法。
- `execute-case.js`：执行页面、真实存储重读、页面重开、旧快照并发和故障注入，并进行业务断言。
- `restart-worker.js` / `execute-restart.js`：在新进程中真实执行 `app.onLaunch()`（应用启动），可继续加载报价页并再次点击。
- `case-worker.js` / `run-suite.js` / `run.js`：每题独立进程、两轮稳定性比较和统一状态汇总。

## 统一合同

两条入口以后必须共享同一合法性和持久化合同：报价列表直接转订单，以及“记一笔”中经用户确认报价后转订单。本组先打通报价列表测试表面，夹具和断言不绑定转单指令文本，可复用于“记一笔”入口。

来源原文合同固定为：

```text
order.originalText = sourceQuotation.originalText
```

脏关系不得自动修复。悬空目标、错误客户、缺反向关系、仅订单反向指向报价，以及同一报价对应多个订单，都必须明确显示数据冲突、零新增、零正式提交、原数据保持不变。

多商品合同要求 `items[]`（商品数组）的数量、顺序和字段保持；顶层单商品兼容字段与第一项一致；总金额与明细无法解释时必须阻断。普通转单不得新增或修改待收款、收款、定金、待办、待整理和客户；现有商品目录与转换进度副作用会被精确记录。

幂等是指同一合法报价第一次只产生一次订单、进度、版本和收据；连续点击、页面重开、应用重启、动作重放和两个旧快照竞争都不得产生第二份业务结果或无意义正式提交。

## 故障与重启边界

- 页面重开：在同一隔离存储上创建新的真实 Page（页面）实例，不冒充应用重启。
- 应用重启：通过新进程执行真实 `app.onLaunch()` 和读取；这是进程级冷启动测试，不等同于微信真机磁盘耐久测试。
- 主写前故障：测试专用假微信存储在业务主键第一次 `SET`（写入）之前抛错，生产 `saveState()` 仍真实执行事务回滚。
- 订单构造后、报价回写前故障：第二次真实 `getState()` 返回的内存报价在写 `status`（状态）时由测试访问器抛错。真实 `convertQuotationToOrder()` 已把订单加入临时状态，但尚未调用正式保存；断言最终持久化完全不变。该访问器只存在于测试内存，不是生产字段或假转换函数。
- 保存调用故障：在页面调用真实 `saveState()` 的观测边界抛错，验证页面没有成功提示且持久化不变。
- 并发：两个真实旧状态快照都执行真实转换；第一次正式保存成功，第二次由真实存储版本合同拒绝。
